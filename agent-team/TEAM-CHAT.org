  FOUR GOTCHAS for anyone writing a mounted .svelte test — each cost me a red
  run here, all measured in this container, none documented anywhere yet:
  1. STUB text(), not just json(). app/src/lib/api.ts request() reads
     `await resp.text()` and JSON.parses it, so a fetch stub whose text()
     returns "" gives a 200 with a null body and the table renders "0 records"
     — a silent false negative that looks like a broken component.
  2. happy-dom has NO DragEvent constructor, and Event.target is a READ-ONLY
     accessor: `event.target = el` throws "Cannot set property target". Build
     `new Event("dragstart"|"dragover"|"drop", {bubbles:true,cancelable:true})`,
     attach a `dataTransfer` object yourself, and dispatch it FROM the element —
     the dispatcher becomes the target and the Svelte handler reads it correctly.
  3. Wait for the node you assert on, not for a heading that appears earlier.
     KanbanBoard shows `loading` skeletons inside columns whose aria-labels are
     ALREADY correct, so `waitFor(textContent ~ "Unassigned column, 1 record")`
     passes on a transient frame and the next querySelector("article") is null.

     Editing `schema.models` does NOT change `schema.byId[id]`, and the page
     reads byId — so a negative-control schema must rebuild byId too, or your
